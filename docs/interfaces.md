# 통신과 자원 계약의 설계 체크포인트

이 문서는 앞선 논의의 구현 기준안이다. 아직 구조체·syscall 번호·ABI 버전을 확정한 명세는 아니다.

## 제어와 데이터 경로

작은 제어 요청·권한 전달은 kernel IPC, 큰 데이터는 등록한 공유 메모리와 요청/완료 큐를 사용하도록 설계한다.
각 요청마다 전체 데이터를 복사하거나 새로 매핑하지 않도록 하되, 작은 요청의 공유 메모리 등록 비용도 측정한다.
압축·정렬·장치 제약에 따라 복사가 필요할 수 있으므로 모든 경로가 zero-copy라고 약속하지 않는다.

## 구현 전에 정할 계약

| 영역 | 정할 내용 |
| --- | --- |
| ABI 표현 | 명시적 폭·정렬·엔디언·버전·길이 검증. Rust 참조·trait object를 프로세스 간 ABI로 전달하지 않음 |
| 핸들 | 객체 종류·권한·소유권·이전/복제·폐기·세대·재사용 규칙 |
| 공유 버퍼 | 등록한 객체·offset·length·접근 권한·대여 기간·경계 검증 |
| 큐 | 생산자/소비자 수·capacity·overflow·순서·atomic memory ordering·알림 누락 방지 |
| 비동기 요청 | request ID·완료·취소·timeout·재시도·중복 처리의 의미 |
| 서비스 | 안정적 서비스 ID와 프로세스 ID의 분리, 인스턴스 세대, 재연결 |
| DMA | pin/unpin·IOMMU mapping·장치 중단·권한 회수·늦은 완료 처리 |
| 파일/페이저 | VFS handle 수명·파일-backed mapping·dirty page·flush·서비스 장애 처리 |

공유 페이지는 클라이언트가 바꿀 수 있는 비신뢰 입력이다. 검사한 length/offset과 실제 접근 사이의 변경까지 고려한다.
서비스 내부 상태나 불필요한 DMA 권한을 공유하면 고장 격리 목표를 훼손한다.

## 서비스 교체 기준안

정상 교체: 새 요청 접수 제한 → 진행 중 요청 정리 → 장치/DMA 정지 확인 → 상태 인계 → 새 세대 서비스에 권한 부여 → 재연결.
충돌 복구: 기존 인스턴스의 종료 확인 → 자원·DMA 회수 → 장치 및 저장 상태 복구 → 새 세대 시작 → 미완료 요청의 실패/재시도 결정.

위 순서의 구체적인 소유자와 실패 처리는 `supervisor`, `device-manager`, 각 서비스 및 커널 권한 기구가 나누어 맡는다.
커널에는 서비스 프로토콜의 업무 의미론을 넣지 않는다. 핸들·매핑·IRQ 같은 공통 기구를 제공한다.

## 측정

직접 호출 기준, 작은 IPC, 공유 큐를 비교한다. p50/p99 지연, 요청당 cycle, 복사 byte, 상주/공유 메모리, 문맥 전환, 깨우기, 유휴 CPU, 작업당 에너지, 복구 시간과 손실/재시도 요청을 기록한다.
QEMU의 기능 검증과 실제 하드웨어의 성능·전력 검증을 구분한다.
